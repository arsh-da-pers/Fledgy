## Regressions and risks

**1. The `vercel/install-vercel-web-analytics-ev5kw0` branch would break the production build.**
High risk, and the only dependency-touching branch in the repo. Its `package.json` predates
three current dependencies, so merging it **removes `@vercel/blob`, `@vercel/kv` and `mupdf`**
while bumping `@vercel/analytics` `^1.3.1 → ^2.0.1`. `@vercel/kv` backs usage limits,
entitlements and the whole leads dashboard. With no local Node and no regenerable lockfile, a
`package.json` change of this shape is exactly the failure mode this project cannot recover
from quickly. Delete the branch; if the analytics bump is wanted later it has to be a fresh
change against current `main`.

**2. Pricing rule 2 still holds, still unguarded.** $20 bundle > $18 careers and > $9 CV, so
nothing is dominated. Rule 1 also holds ($29 mentor > $20 dearest product) **and throws at
import time**, so it cannot ship broken. Rule 2 has no such check and a **$2** margin. Unchanged
from last week, and it is now the longest-standing known trap in the file.

**3. Three finished blog posts are unpublished** (see *Sitting unmerged*). Not a code defect,
but on a project whose stated bottleneck is demand it is the most expensive thing in this brief.
