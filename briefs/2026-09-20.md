## Regressions and risks

**1. Mentor enquiries are arriving with nobody being told.** (New this week, live now.)
Mentor bookings opened 2026-09-19. `src/app/api/mentors/route.ts:80` calls `sendNotification`,
which is inert without `RESEND_API_KEY`. The enquiry itself is **not lost** — `recordInquiry`
and `recordLead` write to KV first, so it appears in `/leads-dashboard`. But the only way to
learn an enquiry exists is to open that dashboard and look. The mentor session is the $29
product, the priciest thing on the site, and the stated purpose of the soft launch
(`src/lib/mentors.ts`) is to measure demand.

**2. `STRIPE_WEBHOOK_SECRET` is unset, so the webhook backstop is not running.** There are two
grant paths, and the mitigation is real but partial:
- `/unlock` (`src/app/unlock/page.tsx:61`) verifies the session with Stripe directly and grants
  on landing, so a buyer who completes the redirect is unlocked. This is deliberate and
  documented at the top of that file.
- The webhook (`api/stripe/webhook/route.ts:88`) is the backstop for anyone who *doesn't* land
  — closes the tab at Stripe, loses connection on redirect, or pays by an async method that
  settles later. Right now that person is charged and granted nothing, with no automatic
  recovery. Stripe also retries failing endpoints for a few days and eventually disables them,
  so the endpoint's state in the Stripe dashboard is worth checking (not visible from here).

**3. Pricing rule 2 holds, but is unguarded.** Rule 1 (mentor dearest) passes — $29 > $20 —
*and is enforced by a throw at import time*, so it cannot ship broken. Rule 2 (bundle costs
more than either product it contains) also passes — $20 > $18 and $20 > $9 — **but has no
equivalent check**. The margin is $2. A $3 cut to the bundle, or a $3 rise in the careers
report, silently makes the standalone careers report strictly dominated with no build-time
error. The file documents both rules as load-bearing; only one is actually defended.

**4. Two blog branches would inject duplicate slugs if merged.** See *Sitting unmerged*. Both
posts are already live on main; the branches are stale duplicates, not pending work.

**5. Vercel Web Analytics ships a beacon to a product that is off.** `<Analytics />` and its
dependency are in the build but the project has no Web Analytics enabled, so the data is going
nowhere.

**Verified clean:**

- **No dependency changes.** `git log --since='7 days ago' -p -- package.json package-lock.json`
  is empty. `npm ci` is safe.
- **Paywall slicing rule holds in all three routes.** Each prompt asks for the *full* ranked
  answer and says the server decides how much is shown — `essay/route.ts:99`, `cv/route.ts:102`,
  `careers/route.ts:182` — and each route slices from the **end** server-side:
  `allTips.slice(-3)` (essay:140), `allTips.slice(-2)` (cv:140), `careers.slice(-1)`
  (careers:213). No route asks the model for less.
- **`leads.ts` still parses every KV key it scans.** It scans two prefixes, `fledgy:tools:*`
  and `fledgy:usage:*`, and takes the email as the segment after the **last** colon, which reads
  both the old `fledgy:usage:<email>` and the current `fledgy:usage:<tool>:<email>`. Every other
  `fledgy:` family — `ent:`, `report:`, `bonus:`, `referredby:`, `referralpaid:`,
  `stripe:session:` — is not scanned, and the `includes("@")` guard would reject
  `fledgy:stripe:session:<id>` anyway. No garbage rows. *Latent gap, not a break:* a buyer with
  a `fledgy:ent:` key but no usage key would not appear on the dashboard — in practice everyone
  runs a free tool first, which writes both.
- **No failed deploys.** 15 of 15 READY.

## Suggested next

1. **Set `RESEND_API_KEY` in Vercel production.** It is a dashboard field, no code, no deploy
   risk — and it is the only thing standing between a $29 mentor enquiry and somebody knowing
   it arrived. Bookings have been open since 19 Sept; until this is set, the soft launch only
   measures demand for anyone who remembers to check the dashboard.
2. **Prove the money path with one real charge, then set `STRIPE_WEBHOOK_SECRET`.** Payments
   have been live 10 days with no charge ever taken, so the $5 essay product is the cheapest
   possible way to test the whole rail end to end — buy it, confirm the unlock, refund it. Do
   this *before* relying on the webhook, then add the secret so the backstop covers buyers who
   never reach `/unlock`.
3. **Pick one analytics system and make it real.** Either enable Web Analytics on the Vercel
   project (the beacon is already shipping) or drop `<Analytics />` and treat Clarity as the
   single source. The bottleneck is demand, and right now this brief cannot report a single
   pageview — so there is no way to tell whether this week's three posts, the IndexNow
   submission, or the mentors page moved anything at all.
