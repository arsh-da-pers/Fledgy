## Regressions and risks

**Invariant 1 — mentor session is the dearest thing: HOLDS.** `MENTOR_CENTS` 2900 >
dearest product 2000 (bundle). Enforced at import time by the `throw` at
`src/lib/products.ts:115`, so a violation fails the Vercel build rather than
shipping.

**Invariant 2 — bundle costs more than either product it contains: HOLDS, but by
$2.** Bundle 2000 > careers 1800 > cv 500. **It is not enforced in code.** The file
documents rule 2 as loudly as rule 1 (lines 19–23) but only rule 1 has a runtime
guard. After `5ac5d4c` dropped `CV_CENTS` 900 → 500 the margin is $2: any future
rise in `CAREERS_CENTS` above 2000, or any drop in `BUNDLE_CENTS` below 1800,
silently makes the $18 careers report strictly dominated and unsellable — with no
build error. The missing guard is four lines and mirrors the one above it.

**Paywall slicing rule: HOLDS in all three routes.** Each prompt asks for the full
ranked answer and the server slices the free tier off the END:

| Route | Prompt asks for | Free tier |
|---|---|---|
| `src/app/api/essay/route.ts:148` | "Give the FULL review — every fix worth making" | `allTips.slice(-3)` — weakest 3 |
| `src/app/api/cv/route.ts:149` | "Give the FULL review — every fix worth making" | `allTips.slice(-2)` — weakest 2 |
| `src/app/api/careers/route.ts:222` | "ORDERED BEST-FIT FIRST… this ordering is load-bearing" | `careers.slice(-1)` — weakest 1 |

All three also instruct the model never to mention free/paid/unlocking, and all
three gate on `PAYWALLS_ENABLED && entitled`. No regression.

**`src/lib/leads.ts` key parsing: still correct.** Every `fledgy:` prefix in `src/`
that the dashboard scans ends in the email. `leads.ts` scans `fledgy:tools:*` and
`fledgy:usage:*`, takes the segment after the LAST colon, and discards anything
without an `@` — which reads both the old `fledgy:usage:<email>` and the current
`fledgy:usage:<tool>:<email>`. No key gained or lost a segment this week.

One structural gap, not a break: the scan covers only those two families, so an
email known **only** from `fledgy:ent:<email>` (a purchase) or
`fledgy:lead:<email>` outside the `fledgy:leads` set would not appear. In practice a
buyer is always a prior tool user, so nothing is hidden today. Noting it because the
first real customer is the case that tests it.

**Dependency changes in the window: none.** `git log --since='7 days ago' -p --
package.json package-lock.json` returns nothing across all branches. `package.json`
and `package-lock.json` on `main` are untouched and in sync.
